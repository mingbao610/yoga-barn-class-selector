# 两堂课，帮助做一个选择

用于最终选课结果及用户要求美化当前结果；只是调整呈现时复用本轮已核实的资料，不重启问卷或重读身体数据。日期或决策条件变更时再核查。

## 信息顺序

- 结果外的一句话：推荐方向和主要取舍，例如「想躺着听声音选 A；还想做些体式选 B」。
- 顶部小字：目标日期、乌布时间、核查时间；明确是推荐还是待确认候选。
- 两列使用相同次序：中文短标题、官方英文名、起止与时长、老师与教室。
- 差异用相同的 3–4 个维度对齐，优先呈现实际参与方式、动作/保持要求、指导依据、适合怎样的体验。用具体行为，不用无依据的强度档位或匹配分数。
- 每列费用状态和登记安排保持可见。课卡待确认、教师待定或时间冲突不能藏进折叠区。来源、核查细节可放在「来源与核查」中。
- 每项一个选择按钮，不预选。用户选的是意向，不是报名；按钮回传一句自然语言，保留日期、英文课名、当地起止和未解决的硬条件，不发送 JSON 或内部工作指令。

## 呈现与降级

有 visualize 能力时先读其规范，将 assets/class-comparison.html 复制到当前任务的持久输出目录后填写 comparisonData。共享模板不保存个人数据或固定当天课表。宽屏两列，窄屏上下排列，标题与正文分层，少量强调；不加装饰图表、疗效承诺或编造配图。

普通 Markdown 使用「项目｜A 课程｜B 课程」对照表，最多 6 个关键维度，结尾让用户回复 A/B。避免每一行都加粗；加粗标记紧贴文字，不写成 `**时间： **`，以免原样显示。宿主没有内联能力或用户报告显示失败后，直接用此降级，不反复生成同一形式。

两项未满足 card_only 等硬条件时，显式标「待确认候选」；按钮文案用「优先核实 A/B」，回传保留原限制，不把点击当作接受额外付费。可确认项不足两项时保留真实数量。

使用 sendFollowUpMessage 后只报告发送入口已调用，实际收到新用户消息才继续；无宿主支持或发送失败时展示可复制的自然语言。不得借选择自动写日历、报名、付款或联系场馆。
